## push.cmd 报错「Test-Path : 路径中具有非法字符」
- 根因：`core.quotePath` 默认 true，git 把中文路径 C-style quote 成 `"src/content/push.cmd - \345\277\253...lnk"`；`push.ps1` 第 169 行把它直接喂给 `Test-Path -LiteralPath`，引号在 NTFS 是非法字符，脚本在 `[3/4] 提交` 阶段崩。
- 触发文件：`src/content/dev.cmd - 快捷方式.lnk`、`src/content/push.cmd - 快捷方式.lnk`（误拖进内容目录的 Windows 快捷方式），已被失败脚本的 `git add -A` 加进暂存区。
- 修复：
  - `scripts/push.ps1` 两处 git 路径输出加 `-c core.quotePath=false`（`status --porcelain` / `diff --cached --name-only`）；体积检查 foreach 加 try/catch，极端文件名不再带崩发布流程。
  - `.gitignore` 加 `*.lnk`。
  - `git restore --staged -- ':(glob)src/content/*.lnk'` 移出误入暂存区的快捷方式（文件本身没删，用 pathspec glob 避开中文字面量）。
  - `push.cmd` 修显示错字 `dDone` → `Done`。
- 验证：PowerShell 5.1 `Parser::ParseFile` 语法 0 错误；按修复后逻辑遍历 21 个暂存路径，errors=0 / found=19 / skipped=2（两个已删除 PDF 属正常），中文 lnk `exists=True` 且无引号、无八进制转义；`push.ps1` 的 UTF-8 BOM 保留、整文件 UTF-8 解码通过（丢 BOM 会被 GBK 读崩）。
- 没做：没有真的 commit / push。失败脚本已执行过 `git add -A`，暂存区仍有 19 个文件（`.obsidian/`、两个 PDF 删除、CSS/字体改动、截图等），重跑 `push.cmd` 会一并提交，需用户自己确认。
