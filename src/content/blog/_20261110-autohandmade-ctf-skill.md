### 未使用任何skill时

```

# MioCrypt2.0 —— 一把只会锁、不会开的锁

> 附件：`MioCrypt2.0.exe`、`flag`、`README.txt`。  
> 目标：从被加密的 `flag` 里还原明文。  
> 一句话：这题的解法不是把锁撬开，是发现锁匠把钥匙孔做成了玻璃的。

## 零、先说结论

| 项目        | 值                                                        |
| --------- | -------------------------------------------------------- |
| 加密算法      | `AES-256-ECB`，零 IV、无填充                                   |
| 密钥封装      | `RSA-2048-OAEP-SHA256`，公钥硬编码在 `.rdata`                   |
| 程序本身的解密能力 | 无。导入表里没有 `BCryptDecrypt`，二进制里没有私钥                        |
| 样本文件      | 8,389,961 字节 = `MIOCRYPT2`(9) + 密钥块(256) + 密文(8,389,696) |
| 密文块数      | 524,356                                                  |
| 其中完全相同的块  | 506,926（96.68%）                                          |
| 落在斜带上的块   | 17,362（3.31%），即文字本身                                      |
| 明文形态      | 2048×2048、16 bpp 的位图，图上斜排一行字                             |
| 图上文字      | `1MioChanIsAlwaysRight0000Zako`                          |
| **Flag**  | **`ISCTF{1MioChanIsAlwaysRight0000Zako}`**               |

密钥每次运行都随机生成，256 字节的密钥块里没有任何可反推的东西。走正常的解密路线是死路。真正能用的东西只有一个：ECB 这个模式本身会把相同的明文块压成相同的密文块。也就是说，不需要密钥，光看密文的重复结构，就能把明文图的轮廓重新画出来。

## 一、先弄清这程序是干什么的

用 Detect It Easy 拖进去看一眼：`PE64`、`GUI`、MSVC 编译、**无壳**。无壳意味着可以直接读反汇编，不必先脱壳。

双击运行，出来的界面很唬人：红底标题 `Ooops, your flag has been encrypted!`，左边一张锁的图，右边写着付款倒计时的截止时间是 2026-11-20 17:00。看着像勒索软件。

但点一下 `Decrypt`，弹出来的是「解密还没…」。再点另一个按钮，弹「杂鱼的余额检查完毕：」。

**界面是道具。** 程序没有解密能力，这两个按钮只负责 `MessageBoxW`。

真正有用的信息要去实验里拿。把 exe 复制到一个空目录 `test\`，塞一个 1024 字节的假 `flag` 进去，然后运行：

- 运行前 1024 字节，运行后 1289 字节，文件头变成 `MIOCRYPT2`。
- 265 字节的固定开销，正好等于魔数 9 加 256。
- 密文段长度仍是 1024，没变长，说明**不做填充**。

再多做三组对照，程序的脾气就清楚了：

| 输入                  | 结果                     | 说明            |
| ------------------- | ---------------------- | ------------- |
| 1024 字节的 `flag`     | 加密，长度 +265             | 16 的整数倍才处理    |
| 1000 字节的 `flag`     | **原样不动**，退出码 0         | 不补位、不报错，直接跳过  |
| 1024 字节的 `test.bin` | 原样不动                   | 文件名写死为 `flag` |
| 已加密的文件再跑一次          | 不再加密，`MIOCRYPT2` 只出现一次 | 有幂等检查         |

## 九、三个容易走偏的地方

**一是比例。** 524,288 个块如果按 256 行去排，图会变成 2048 高、256 宽的一条竖线，看起来就是噪点。必须记着「1 块 = 8 像素宽」，横向拉 8 倍。

**二是旋转方向。** 字从左上往右下倾斜的话该转 +45°，这题是反的。转错了会得到一张镜像的图，怎么读都不对。

**三是那行假 flag。** 备注里 `ISCTF{nice_try_but_no}` 摆得最显眼，字面意思就是"想得美"。它和密文里的内容毫无关系。

最后补一句这题的技术点：密钥、私钥、RSA 参数全部正常，唯一的问题出在模式选择上。把同样的算法链条换成 CBC 或 GCM，这题就真的做不出来了。

### 使用ljagiello老哥的skill：

```
# MioCrypt2.0

## Summary

程序把 `flag` 就地覆写成 `MIOCRYPT2` + RSA 封装的 32 字节会话密钥 + AES-256-ECB 密文，私钥不在附件里，正常解密无解。破口在 ECB 的确定性：密文里 96.68% 的块完全相同，据此把每个块打成二值像素，可直接还原出 2048×2048 的明文位图。

## Solution

### Step 1: 确认程序只加密、不解密

DIE 显示 `PE64`、`GUI`、无壳，直接静态分析。`bcrypt.dll` 的导入表里 `BCryptEncrypt` 在，`BCryptDecrypt` 不在；`.rdata` 中有 `AES`、`ChainingModeECB`、`ObjectLength`，且 `BCryptEncrypt` 的 `pbIV = NULL`、`dwFlags = 0`——零 IV 加无链式标志即 ECB。同区域的 `RSAPUBLICBLOB` 共 283 字节，魔数 `RSA1`，`bitlen = 2048`，公钥指数 `0x010001`，二进制内无任何私钥材料。

用同一份 1 KB 明文跑两次，256 字节密钥块与整段密文均不同，说明会话密钥由 `BCryptGenRandom` 每次重新生成。密钥路线至此作废。

### Step 2: 用块频次还原明文图

`flag` 长 8,389,961 字节：`MIOCRYPT2` 占 9、密钥块 256、正文 8,389,696。正文切成 524,356 个 16 字节块，众数块出现 506,926 次，占 96.68%。ECB 对相同明文块输出相同密文块，因此这个比例意味着明文绝大部分是同一片纯色。

前 68 块（1,088 字节）是位图头，余下 524,288 块正好排成 2048×256。按 16 bpp 计算，一个块覆盖 8 个像素宽，横向拉伸 8 倍才是真实比例。

### Step 3: 读字并核对

`plain_line.png` 是一行斜排文字。两个易错点：BMP 的行序自底向上，不先上下翻转会得到镜像的字；比例按 1 块 = 8 像素算错，会得到一条 256 宽的竖线，看着像纯噪点。

核对用三个可量化的数：包围盒 2,566×160、宽高比 16.04、8 连通域 28 个。用 `georgiai.ttf` 200 px 渲染候选串，同一量法得 16.35 与 31，同档。视觉上逐字符可读，内容与备注里的 `Hint` 一字节不差。

备注末行的 `ISCTF{nice_try_but_no}` 是诱饵，与密文无关。

## Flag

ISCTF{1MioChanIsAlwaysRight0000Zako}
