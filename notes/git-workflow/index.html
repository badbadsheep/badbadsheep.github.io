    我的 Git 工作流

    📄 约 399 字⏱️ 阅读约 1 分钟

    一份给「一个人维护一个仓库」场景的精简约定，不追求完备，只求能长期坚持。

    分支模型

    只有两条长期分支：

    • main：随时可发布的版本，每次推送都会触发自动部署
    • draft：不确定要不要发的内容暂存在这里

    写一篇文章的完整流程：

    git switch -c post/giscus-comments   # 从 main 开分支
# ... 写内容、预览、修改 ...
git add -A
git commit -m "post: 给静态博客接上 giscus 评论"
git switch main
git merge --no-ff post/giscus-comments
git push
git branch -d post/giscus-comments

    为什么用 --no-ff

    保留一次合并提交，将来 git log --graph 能清楚看到「哪几个提交属于哪篇文章」， 回滚时直接 git revert -m 1 <merge> 即可。

    提交信息约定

    <类型>: <一句话说明>
    类型 用途
    post 新增或大改一篇文章
    fix 修正错别字、坏链接、事实错误
    style 只动样式，不动内容
    config 改 mkdocs.yml、工作流、依赖
    chore 其它杂项

    例子：

    post: 用 MkDocs Material 搭一个 GitHub 博客
fix: 修正 giscus 配置章节的错别字
config: 搜索插件启用中文分词

    几个有用的命令

    查看某篇文章的修改历史

    git log --follow -p -- docs/blog/posts/comments-with-giscus.md

    临时藏起未写完的改动

    git stash push -m "wip: 一半的草稿"
git stash pop

    找出所有失效的内部链接（构建时会自动校验）

    .venv\Scripts\mkdocs build --strict

    写作与发布的边界

    一个值得坚持的原则：main 分支上的内容必须是可以被公开阅读的。

    • 没写完的文章放在 draft 分支，或者用 front matter 的 draft: true 标记
    • 本地跑 mkdocs serve 时草稿可见（draft_on_serve: true），构建发布时自动隐藏
    • 任何「暂时不想被看到」的内容，不要推送到远端仓库 —— 即使之后删掉，提交历史里依然能找到

    备份

    仓库同时存在三个地方，基本不用担心丢失：

    1. 本地工作副本
    2. GitHub 远端仓库
    3. 每次 git clone 出来的任何一台机器

    如果还想更稳妥，可以再挂一个私有镜像：

    git remote set-url --add --push origin git@github.com:your-name/blog-mirror.git
